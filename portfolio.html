Demo portfolio & trade execution

Balance, positions, fills and order placement against your Kalshi demo account. Requests are signed in this browser tab. The private key is held in memory only, is never written to storage, and is never sent anywhere except the demo API.

Read this before adding a key

  • Use a demo API key created at demo.kalshi.co/account/profile ↗. Never paste a production key.
  • Demo credentials are separate from production and demo funds are mock only. Source ↗
  • Reloading the page drops the key from memory — that is deliberate. You will re-paste it to trade again.
  • Requests are signed against /trade-api/v2 + path with the query string stripped, RSA-PSS/SHA-256 (salt = 32) or Ed25519. Signing rules ↗

⚠ The price scale for a NO order is contradictory in the official docs

This form sends side: "ask" when you buy NO, and it sends price unchanged. Two official pages disagree on what that price means for a NO order, and this session could not settle it without a demo key, so it is left visible rather than guessed at:

  • NO-lot price (multiples of $0.01). Order direction ↗ says an order at price p with outcome_side=no is matched by an order at the same p with outcome_side=yes, so the price does not change with the side.
  • YES-leg price. Create Order (V2) ↗ defines its side field as "bid means buy YES, ask means sell YES … this endpoint quotes everything from the YES side", with "ask = sell YES = buy NO at 1 - price".

How to avoid the ambiguity entirely: check the market first (step 3 loads its grid when you type a ticker) and read the resulting price as the price you are paying. If you want the opposite exposure at a known price, place that order as a YES order of the complementary market instead of a NO order here. Tracked as Flagged NF1; the field itself is not disabled because both readings say the exposure is a NO position.
