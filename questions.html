Questions, information and answers before any decision

Every decision this dashboard implies depends on facts. This page states each question plainly, what we know, what we do not know, the answer we can support today, and — where the answer is missing — exactly how to obtain it.

Reading the confidence column

answered backed by an official source or a live API observation · partly answered some evidence, one gap remains · not answerable yet the data needed does not exist for this build. No question is closed by opinion.

A demo API key pair Unlocks balance, positions, fills and order placement; without it the portfolio and strategies pages have no data to analyse. Create one at demo.kalshi.co/account/profile ↗ (docs ↗), then load it on the Portfolio page. Account owner
Trade history long enough to judge a strategy Six strategy rules are catalogued but none can be scored. Any "best strategy" claim would be invented. Place a deliberate set of demo trades — at least tens of fills per rule — then reload the Strategies page. It computes from live fills only. Account owner
Gas-price market coverage on the demo exchange The gas topic currently has no open demo markets, so that page cannot demonstrate live data. Re-scan on a different day, or confirm whether gas markets are restricted to production. The page already reports its scan size so the claim is falsifiable. Kalshi demo operations
Broker-side cost basis for realised P&L Profit per closed trade needs the entry and exit prices paired per position. Derive it from GET /portfolio/fills paired by ticker and outcome side, and reconcile against realized_pnl from positions. Implementation work
Whether WebSocket streaming works from a browser Streaming would give sub-second price updates instead of 2-second polling. Test an authenticated WebSocket handshake from a browser context, or add a small relay. Until then polling is used and labelled. Implementation work
