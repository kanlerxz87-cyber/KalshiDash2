Executive summary

What this project is, what is proven, what is not, and what to decide next. Written 2026-11-20 against the Kalshi demo environment and the official API documentation.

1 · What was built

A live, no-build dashboard for the Kalshi demo exchange covering the five requested topics — gas prices, elections, culture, crypto and golf. It discovers markets from the live API, ranks them by money traded, follows each one until the exchange reports a yes or no result, charts contract price against time, and shows resting liquidity at every price level. Two scrolling alert feeds report every $0.10-or-larger swing while the page is open — one with all alerts, one filtered by a transparent High-ROI rule set — and four simulated strategies trade automatically on those alerts, with per-strategy P&L settled on the exchange's own yes/no results. Chart windows mark every sharp move and link it to the event, the API data, and the sources the market settles from. A separate portfolio page can read the demo account and place orders, and a strategies page categorises whatever fills actually exist.

2 · What is proven

  • The demo REST and WebSocket endpoints in the brief match the official documentation exactly.
  • Public market data — markets, events, order books and candlesticks — reads without credentials, and CORS permits this site's Pages origin on nine endpoints.
  • Resolution is unambiguous: settled markets return result as yes or no. A 200-market sample was 82 yes, 118 no, none blank.
  • The current order route is POST /portfolio/events/orders; the legacy route returns HTTP 410 with deprecated_v1_order_endpoint.
  • Order side uses book vocabulary — bid is yes, ask is no — which is the opposite of how a "sell yes" label reads.
  • No seconds-resolution price history exists: the candle endpoint accepts only 1, 60 and 1440 minutes, and a 5-minute request was rejected live.

3 · What is not proven

  • No order has ever been executed from this site — no demo key was available. Route existence and schema are verified; the end-to-end fill is not (F1).
  • No performance figure exists. With no fills there is no realised P&L, no win rate and no ranking of the six strategies (F2).
  • The gas topic is empty in the demo environment — zero open gas-price events in a 1,000-event scan (F4).
  • Streaming is unconfirmed in a browser; polling is used and labelled (F10).
  • The public rate-limit budget is unpublished (F3).

6 · How this site stays honest

Blank beats wrong

A value the API did not return renders as n/a, not zero. A price of $0.00 and a missing price are different facts.

Every row is traceable

Computed figures name their formula inline; API figures name the endpoint. The Verification page links each claim to its official source.

Limits are stated, not hidden

The seconds-resolution gap and the accumulate-from-live approach are written on the chart itself, so the line is never mistaken for exchange history.

7 · Method

Facts were captured from the official API by CI, because the build sandbox cannot open TLS connections to Kalshi hosts. Each capture is committed to reports/ with a timestamp and the commit it ran against, so every claim can be re-derived. Documentation claims link to docs.kalshi.com ↗. Signing rules were additionally proved by a deterministic 6-check self-test.
