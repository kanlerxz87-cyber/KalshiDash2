**Purpose:** a no-build, read-only-by-default dashboard for the Kalshi **demo** exchange. It organizes currently discovered events in five requested topics—gas prices, elections, culture, crypto, and golf—tracks exchange-reported yes/no resolution, displays price/liquidity, and provides a separate browser-only paper-trading experiment.

## Official demo APIs

The dashboard's configured read base is Kalshi's recommended demo REST endpoint `https://external-api.demo.kalshi.co/trade-api/v2`; its WebSocket setting is `wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2`. The documented alternatives are `https://demo-api.kalshi.co/trade-api/v2` and `wss://demo-api.kalshi.co/trade-api/ws/v2`. Public market reads do not require credentials. Portfolio and trading requests require a separate demo API key and private key; credentials are entered in the Portfolio page and kept in that browser tab. No user credentials are included in the repository.

Official references: [Demo environment](https://docs.kalshi.com/getting_started/demo_env), [API environments](https://docs.kalshi.com/getting_started/api_environments), [Get Events](https://docs.kalshi.com/api-reference/events/get-events), [Get Markets](https://docs.kalshi.com/api-reference/market/get-markets), [Get Event](https://docs.kalshi.com/api-reference/events/get-event), [Market lifecycle](https://docs.kalshi.com/getting_started/market_lifecycle), [Market settlement](https://docs.kalshi.com/getting_started/market_settlement).

## What is implemented

- **Overview and topic pages:** live event discovery for gas, elections, culture, crypto, and golf; ranking controls; a derived volume × current last YES-price proxy (`volume_fp × last_price_dollars`) alongside contract volume and open interest. This proxy is not actual dollars traded, and it is still what the ranking column shows; the **official** traded-dollar figure is now available beside it on every category page (see *Dollars actually traded* below), which is why [A11](flagged.html#A11) is mitigated rather than closed. Event detail and official per-row source links are included.
- **Dollars actually traded (official):** each category page carries an on-demand panel that sums `GET /markets/trades` for the topic — Σ(`count_fp` × the price of the side the taker bought), using each trade's own recorded `taker_outcome_side` and its `yes_price_dollars` or `no_price_dollars`. It states the requested window, the `created_time` span of the trades actually returned, how many markets it read, and how many open markets it skipped; a market whose pages could not all be read is reported as `n/a` and withholds the topic total, never contributing a partial sum. A trade with no recorded taker side, or no price on the side taken, is excluded and counted rather than valued by assumption, and each market measured carries its own response link so a row can be re-added by hand. It is a ranked sample of the highest-volume markets, not a census. Source: [Get Trades](https://docs.kalshi.com/api-reference/market/get-trades); arithmetic and the exclusion rules covered by `tests/dollar-volume.test.mjs` (31 checks) and the category DOM suite.
- **Charts and liquidity:** time-versus-price charts with short live samples and longer official candlesticks; order-book depth shows contracts at each resting price level. Kalshi's candlestick API does not provide seconds-resolution history: short windows are samples accumulated while the tab is open. See [candlestick docs](https://docs.kalshi.com/api-reference/market/get-market-candlesticks) and [orderbook response docs](https://docs.kalshi.com/getting_started/orderbook_responses).
- **Resolution:** tracked and recently settled markets show the API's `result` field (`yes` or `no`); the dashboard does not infer outcomes from price.
- **Live alerts:** [Live alerts](https://kanlerxz87-cyber.github.io/KalshiDash2/alerts.html) compares `last_price_dollars` between readings and against the exchange's own `previous_price_dollars`, and generates an alert for an absolute change of at least $0.10 in either direction. Every message states which comparison produced it, and a table view of the same events links the official API response behind each price. It has an **All alerts** feed and a **High-ROI watch** filtered by explicit spread, price-band, quote-availability, and open-interest rules. The label is not a claim of predicted or measured ROI.
- **Live feed (WebSocket ticker):** the alerts page can subscribe to Kalshi's documented `ticker` channel, which flushes changed markets about once per second. A browser cannot open that socket itself — the handshake requires `KALSHI-ACCESS-*` headers that the Web Platform `WebSocket` constructor cannot send — so `scripts/relay.py` opens the socket server-side and republishes the frames to the page as same-origin Server-Sent Events. The relay needs a **demo** API key, which this repository does not contain, so on the published GitHub Pages site the page runs on the REST poll and its status pill says so. The WebSocket path detects swings between consecutive readings only, because the ticker payload carries no `previous_price_dollars`; the ticker also coalesces changes, so an intermediate price may never be observed. These three limits are published as Flagged items W1, W2 and W3.
- **Strategy tester:** strategy rules are replayed over official one-minute candlesticks and every simulated trade is scored against the market's own `settlement_value_dollars`. YES and NO entry prices are calculated using the complement relationship (NO cost = 1 − YES quote); a pre-existing NO-side P&L error is corrected and flagged as F17, so prior NO-side results should be regenerated. Results now include a seeded random-control baseline, breakdowns by topic and direction, and a CSV export with official-source URLs. The baseline is reproducible for a given ticker/history, but is not a prediction or a statistical significance test. The assumptions (fees modelled from the official schedule; no spread, no slippage) are printed above the results, and the simulated result remains optimistic by an amount the site cannot quantify (F15). A live paper-trading book on the same page is driven by the same alert engine as the Live alerts page.
- **Paper strategies:** four automatic browser-local paper strategies (Follow/Fade on All alerts and High-ROI watch). They assume entry at the displayed ask, mark open positions at the best bid, and settle only on the official yes/no result. They do not place exchange orders. Simulated fills omit fees, slippage, and queue position; outcomes are not evidence of a profitable live strategy.
- **Portfolio and order placement:** balance, positions, fills, and guarded V2 demo order placement are available when the user supplies a demo key pair. No key was supplied for this build, so no real account performance or end-to-end fill is claimed. See [Create Order V2](https://docs.kalshi.com/api-reference/orders/create-order-v2), [Get Fills](https://docs.kalshi.com/api-reference/portfolio/get-fills), and [Get Positions](https://docs.kalshi.com/api-reference/portfolio/get-positions).
- **Decision and audit pages:** Strategies, Suggestions, Questions, Verification, **Sources** and Flagged for Review. The
  Sources page lists every official page the site depends on with what each is used for and how it was checked
  (read in full, matched against the official `llms.txt` index, or unverified), and its register is tested so the
  page cannot drift from its data (`tests/sources-page.test.mjs`). Dynamic market-data rows on the published root pages link to an official endpoint response; private-account rows link to the official endpoint documentation.

## Coverage and limitations (not assumptions)

- Alerts poll only while the browser page is open. The current universe is deliberately partial: at most 12 pages of 200 open events are scanned, then the top 30 open markets per topic by the configured volume × last YES-price proxy are watched. Markets outside that set can move without an alert. See Flagged items A2, A6, and A11.
- A price alert observes the last traded price between readings. Quote-only movements and moves that occur and reverse inside one poll are not detected (A3). Event `settlement_sources` are context links, **not verified causes** of price jumps (A4).
- The live WebSocket ticker feed, where it is running, coalesces changes into a roughly one-second flush, so an intermediate price may never be seen and a swing that reversed inside one window is invisible (W3). It carries no `previous_price_dollars`, so the exchange-reference comparison exists only on the REST path (W2). On the published GitHub Pages site the feed is not running at all, because it needs a demo API key and a relay process the visitor runs themselves (W1).
- The High-ROI watch is a rule set, not a validated model (A1). Paper P&L is optimistic because fees, slippage, and queue position are not modeled (A5).
- The gas-price page may be empty when no matching open demo events are found; the 2026-11-20 scan recorded zero in its 1,000-event sample (F4). This is not evidence that the production exchange has no gas markets.
- Browser streaming has not been verified; polling is used (F10). Public unauthenticated numeric rate limits are not published in the cited docs (F3).
- A moderate security advisory affected the **test-only** `esbuild@0.24.2` dependency. That lockfile was upgraded to `esbuild@0.25.0` (`tests/dom/package-lock.json`, the first version the advisory lists as patched) and the item is recorded as mitigated A10 with the [official GitHub advisory](https://github.com/advisories/GHSA-67mh-4wv8-2f99). esbuild is not a runtime dependency of the static Pages site.
