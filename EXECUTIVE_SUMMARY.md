# Executive Summary — KalshiDash2

**Purpose.** Collect, organize, and analyze the highest-dollar live Kalshi **demo** events in five topics — gas prices, elections, culture, crypto, golf — track each until it resolves (yes/no), and trade/analyze performance on the demo account.

**Data source (official).** Kalshi demo REST API `https://external-api.demo.kalshi.co/trade-api/v2` (recommended) and WebSocket `wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2`; also-supported hosts `https://demo-api.kalshi.co/trade-api/v2` / `wss://demo-api.kalshi.co/trade-api/ws/v2`. Public market data needs no key; trading/portfolio needs a signed API key (RSA-PSS SHA-256 or Ed25519; timestamp in milliseconds; signature over `timestamp + METHOD + full-path-without-query`). Demo uses mock funds and demo credentials are separate from production. Sources: [demo env](https://docs.kalshi.com/getting_started/demo_env), [authenticated requests](https://docs.kalshi.com/getting_started/quick_start_authenticated_requests), [create order](https://docs.kalshi.com/getting_started/quick_start_create_order) (all fetched and verified 2026-11-20; full list on the site's Sources page).

**What was built.** A static GitHub Pages site in `docs/` (no build step): landing + executive summary; live dashboard (four explicit rankings — est. dollar volume *derived* = volume × last price, volume, 24h volume, open interest — price charts with seconds/minutes/hours windows via official candlesticks, order-book liquidity with contracts-per-price); category subpages for each of the five topics; portfolio & trading (browser-side signing with the user's own demo keys, official order body, guarded order placement); resolved-event tracker (official `result` yes/no + `settlement_ts`); trades & strategy (trade log categorized by trade type with a per-type strategy library marked as proposals); analysis by topic/direction/type from real fills only; suggestions with decision gates; open questions; verification table; sources page; and a Flagged for Review page. Repo-side `scripts/kalshi_client.py` + `scripts/analyze_trades.py` cover the same workflow off-browser (Ed25519 supported there).

**Verification rule.** Every value is either returned live by the demo API in the browser (never transcribed into the repo) or linked to an official source. Unconfirmable values are blank + flagged. See `VERIFICATION.md` and `docs/flagged.html`.

**Key risks / unknowns (Flagged for Review F1–F7).** Browser CORS to the demo host unverified until the live site is opened (F1); no demo keys in repo, so portfolio/trading shows empty states by design (F2); in-browser Ed25519 depends on WebCrypto support (F3); topic matching is a keyword heuristic because the API's exact category strings are undocumented (F4); no persistent price history (F5); outcome-joined realized P&L per strategy not computed (F6); "highest dollar amount" is ambiguous — the API reports contracts, not dollars, so the dashboard ranks by four explicit metrics and labels the derived one (F7). See `QUESTIONS.md` for the decisions these map to.
