KalshiDash2 demo

Resolved & tracked events

Two tables. The first lists markets the exchange has already settled, with the outcome copied verbatim from the API result field (yes / no; scalar markets are labelled and not counted as yes/no). The second lists still-open positions of interest so you can see what is being tracked toward resolution.

How resolution is determined

source: market settlement · Get Market
status The market's lifecycle stage. The API documents unopened, open, closed, settled (Get Markets).
result The determined outcome of the market. Values observed in the schema: yes, no, scalar, and the empty string while undetermined. Only yes and no are counted as yes/no resolutions here.
settlement_ts Settlement timestamp. The schema documents it as filled only for settled markets; the table leaves it blank when the API returns nothing.
expiration_value The source value Kalshi used to settle. Copied verbatim; blank when the API returns an empty string.

Settled markets (yes/no)

Request: GET /markets?status=settled, paginated by cursor. Rows are markets whose result is exactly yes or no.

Tracked until resolution (still open)

The live dashboard's top markets are tracked automatically. Click Watch on any row below to keep it here until it settles. When the collector sees the market settle, it moves to the settled table above on the next snapshot. Watches are stored in this browser only (localStorage).

What happens to a watched market

  1. Open. The collector records the market while status is open. Prices, volume and open interest are copied at collection time.
  2. Determined. Kalshi sets result after the settlement source confirms the outcome. Until it does, this page shows the market in the open table and never guesses a direction.
  3. Settled. The market appears in the settled table with its result, settlement_ts and expiration_value exactly as returned.
A settled market leaves the open list only when a later snapshot includes it. If the snapshot banner is stale, the two tables can briefly disagree — the timestamps on each row are the authority, not the page.
