Live alerts

Two scrolling feeds. The All alerts feed shows every swing of $0.10 or more in the last traded price of an open market in the five topics. The High-ROI watch feed keeps only the swings that pass a transparent rule set, ranked by a tradeability score. Simulated strategies run automatically on both feeds. No orders are placed.

Read this before using the feeds

  • Demo data, mock funds. Prices come from the Kalshi demo environment, not production.
  • The High-ROI watch is a rule set, not a model. It checks liquidity and price band. It forecasts nothing, and no return is verified. Replace the rules in assets/js/alerts-core.js with your own model.
  • Two comparisons produce a swing. One is between two consecutive polls of this page; the other is against the exchange's own previous_price_dollars, which is available on the first poll and is the exchange's reference rather than this page's. Every message says which one produced it.
  • There are two possible sources, and the status pill says which is running. With scripts/relay.py running on the same origin, the page reads the Kalshi WebSocket ticker channel, which the exchange flushes about once a second, and a $0.10 move can appear in roughly a second instead of a poll interval. Without the relay the page falls back to the REST poll and says so. Nothing is ever presented as live when it is not.
  • A page cannot open a Kalshi WebSocket by itself. The handshake requires the three KALSHI-ACCESS-* headers, and a browser's WebSocket constructor cannot set custom headers — it takes only a URL and an optional subprotocol list. That is why the relay exists: it opens the socket and republishes the frames. WebSocket quick start ↗
  • Polling only runs while this page is open. A move that happens while the tab is closed is not recorded.
  • The score ranks tradability, not expected return. It adds points for liquidity, spread, depth at the touch, price band, time to close and recent volume. It is not a probability model and it forecasts nothing — the hit rate of each signal is measured on settled demo markets on the Strategy Tester page.
  • Settlement sources are not causes. They are the sources the market says it settles from, shown so you can check news on the same subject. They do not prove why a price moved.

Automated paper strategies

Each alert opens one simulated 1-contract trade per strategy. Follow buys the side the move went toward; Fade buys the opposite side. Entry is the displayed ask for that side. A market is marked at its best bid for that side. A trade settles only when the API reports the market result as yes or no.

Rules, parameters and official sources

Price used for alerts
Last traded price. From REST it is last_price_dollars (Get Markets ↗); from the WebSocket it is price_dollars (Market Ticker ↗). Both are compared between two consecutive readings, and against the exchange's own previous_price_dollars (Get Market).
Tradeability score
Six documented fields — open interest, spread, depth at the touch, price band, time to close, 24-hour volume — summed to 100. A ranking aid, not a probability and not a forecast.
Alert threshold
|change| ≥ $0.10 (the brief's threshold). Moves that happen inside one poll interval are combined into one change.
Live source
The Kalshi demo WebSocket ticker channel. The exchange "combines" changes and "sends one message per changed market" on a flush scheduled every second, so a swing can be seen within about a second of the trade. Reached through scripts/relay.py, which opens the socket (a page cannot) and republishes the frames as Server-Sent Events on /live/stream.
WebSocket authentication
Handshake headers KALSHI-ACCESS-KEY, KALSHI-ACCESS-TIMESTAMP, KALSHI-ACCESS-SIGNATURE, signed over timestamp + "GET" + "/trade-api/ws/v2" — the WebSocket path, not the REST prefix. Quick start ↗
Universe
Top 30 open markets per topic by volume × last YES price proxy, refreshed every 10 minutes. This is a ranking proxy, not actual dollars traded; coverage is partial by design. See Flag A11.
Batch reads
Comma-separated tickers on GET /markets, 25 tickers per request.
Settlement sources
Listed on the event record (settlement_sources) from GET /events/{event_ticker}.
Rate limits
On HTTP 429 the poll interval doubles (capped at 5 minutes) until the API accepts requests again.
