Demo portfolio & trade execution

Balance, positions, fills and order placement against your Kalshi demo account. Requests are signed in this browser tab. The private key is held in memory only, is never written to storage, and is never sent anywhere except the demo API.

Read this before adding a key

  • Use a demo API key created at demo.kalshi.co/account/profile ↗. Never paste a production key.
  • Demo credentials are separate from production and demo funds are mock only. Source ↗
  • Reloading the page drops the key from memory — that is deliberate. You will re-paste it to trade again.
  • Requests are signed against /trade-api/v2 + path with the query string stripped, RSA-PSS/SHA-256 (salt = 32) or Ed25519. Signing rules ↗

NO-order price scale: quoted on the YES leg

This form sends side: "ask" for a NO position and passes the entered price through unchanged. These are the two official descriptions it rests on — read together they answer different questions, as the paragraph below explains:

  • Order direction ↗ says direction does not change the order's price and describes NO and YES orders matching at the same p.
  • Create Order V2 ↗ describes bid as buy YES, ask as sell YES, and says the endpoint quotes the YES side: “Selling YES is economically equivalent to buying NO at 1 - price”.

The two descriptions are about different quantities, not the same one: the Create Order V2 BookSide schema fixes the request field to the YES leg ("this endpoint quotes everything from the YES side"), while the order-direction page describes the matching price, which is the same on both sides. The form therefore sends the price you enter unchanged for a NO position, and a NO contract costs 1 − price. No authenticated order was placed by this project, so nothing here is a receipt for a live fill — see Flagged F20 and NF1.
