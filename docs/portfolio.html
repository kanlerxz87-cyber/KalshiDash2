Portfolio & trading — demo account

Demo only. These endpoints are the Kalshi demo environment, which uses mock funds (demo environment docs). Never paste a production key here. Demo keys and production keys are not interchangeable (environments).
Nothing is pre-filled and nothing is simulated. Balance, positions and fills are read from your own demo account. Orders are submitted to the demo exchange. If you have not added a key, every panel below says so instead of showing placeholder numbers.

1 · Demo API key (this browser tab only)

Create a demo key at demo.kalshi.co → Account → API Keys. Kalshi issues either an RSA key (sign with RSA-PSS, supported here) or an Ed25519 key (not supported here — WebCrypto cannot sign Ed25519). If your key file starts with -----BEGIN RSA PRIVATE KEY----- it is RSA. Sources: API keys · authenticated requests.

no key

Stored in sessionStorage, which is cleared when the tab closes. It is never written to localStorage, never committed, and the key is only used to sign requests sent to external-api.demo.kalshi.co.

How the signature is built

  1. Pre-sign text: timestamp + "GET" + "/trade-api/v2/portfolio/balance"
  2. Sign with RSA-PSS, SHA-256, MGF1-SHA-256, salt length = digest length
  3. Send headers KALSHI-ACCESS-KEY, KALSHI-ACCESS-TIMESTAMP (milliseconds), KALSHI-ACCESS-SIGNATURE (base64)
  4. The timestamp must be within 30 seconds of Kalshi's clock or the request is rejected with 401 header_timestamp_expired
  5. Query strings are excluded from the signed path

Source: API keys — using a key

3 · Place a demo order

Uses the current V2 order endpoint POST /portfolio/events/orders (Create Order V2). Side is bid or ask — ask sells the yes leg, which is the same as buying no (order direction). The legacy /portfolio/orders write endpoints return 410 Gone.

A 201 means the order was accepted, not that it is resting. Check fill_count and remaining_count in the response. Every accepted order is appended to the local trading journal so the Analysis page can report real results.

Pre-flight checks this page runs

  • Ticker is non-empty and exists in the current snapshot
  • Count > 0 and has at most 2 decimals
  • Price is inside 0.01–0.99 and has at most 4 decimals
  • reduce_only is not set (it requires immediate_or_cancel)
  • Demo credentials exist in this tab
