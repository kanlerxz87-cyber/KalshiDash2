F2No demo API keys in this repoTrading/portfolio features require your own demo key ID + private key. No keys were invented, stored, or committed. Without keys those pages show empty states by design — no fabricated balances or trades.S4Create a demo key at demo.kalshi.co (Account & security → API Keys) and paste it on the Portfolio page when ready.
F3Ed25519 in-browser signing is feature-detected, not guaranteedWebCrypto Ed25519 support is still uneven across browsers. The site detects the key type from the PEM (OID 1.3.101.112), attempts Ed25519 via WebCrypto, and raises a clear error if the browser can't sign it. RSA-PSS works everywhere. scripts/kalshi_client.py supports both key types regardless.S4 (Ed25519 signs message directly)Use an RSA key for in-browser trading, or run the Python client (Suggestion S3 if demand justifies a pure-JS Ed25519 implementation).
F4Topic matching is a keyword heuristicThe five topics (gas, elections, culture, crypto, golf) are matched against live /series fields (ticker, title, category, categories, tags) by keyword. The API's exact category strings are not documented (the category filter is exact and case-sensitive), so matches may include or miss series. Every match is shown in the UI so you can audit it. The live category vocabulary was observed 2026-11-20 by the probe workflow (16,643 series; e.g. Elections 5,418, Entertainment 5,255, Crypto 640, Culture 4 — see data/probe/api_surface.json), which is empirical evidence, not documentation.S8 (category filter semantics) + data/probe/api_surface.jsonReview matched series on each category page; refine the keyword lists (Suggestion S7); or propose explicit category strings to filter by.
F5No persistent price historyCharts use live polling (seconds view) and official candlesticks (minutes/hours). Reloaded pages lose in-session polling points; nothing is stored server-side.S10Approve Suggestion S2 (scheduled snapshots) if history across reloads matters.
F6Realized P&L per strategy not computedFills and positions are analyzed live, but joining fills → settlements → realized P&L per strategy is not implemented. No P&L numbers are shown anywhere, rather than guessed ones.S18 Get Settlements (discovery path)Approve Suggestion S4.
