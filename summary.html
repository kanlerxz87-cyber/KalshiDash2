Executive summary

What this project is, what is proven, what is not, and what to decide next. Written 2026-11-21 against the Kalshi demo environment and the official API documentation.

1 · What was built

A live, no-build dashboard for the Kalshi demo exchange covering gas prices, elections, culture, crypto and golf. It ranks the currently discovered events by a derived volume × last YES-price proxy (Σ contracts × last YES price), computed by this site and not actual dollars traded. The API's notional_value_dollars is defined as the value of a single contract at settlement, not traded dollar volume; see Flag A11. Other ranking controls show contract volume and open interest. The site tracks official yes/no settlement and charts price and order-book liquidity, and offers a dedicated Live alerts page with two scrolling feeds for moves of at least $0.10 and automatic browser-local paper strategies. Alerts use last-traded prices between polls; the High-ROI watch is a transparent rule set, not a validated forecast. The Portfolio page supports signed demo-account reads and V2 order placement when the account owner supplies demo credentials.

For exchange behaviour and fields, the evidence column links the official Kalshi documentation. Thresholds, filters, strategies, and the dashboard itself are project choices—not Kalshi recommendations or validated forecasts. The claim register records the source and evidence for each factual claim.

2 · What is proven

  • The demo REST and WebSocket endpoints in the brief match the official documentation exactly.
  • Public market data — markets, events, order books and candlesticks — reads without credentials, and CORS permits this site's Pages origin on nine endpoints.
  • Resolution is unambiguous: settled markets return result as yes or no. A 200-market sample was 82 yes, 118 no, none blank.
  • The current order route is POST /portfolio/events/orders; the legacy route returns HTTP 410 with deprecated_v1_order_endpoint.
  • Order side uses book vocabulary — bid is yes, ask is no — which is the opposite of how a "sell yes" label reads.
  • No seconds-resolution price history exists: the candle endpoint accepts only 1, 60 and 1440 minutes, and a 5-minute request was rejected live.

3 · What is not proven

  • No order has ever been executed from this site — no demo key was available. Route existence and schema are verified; the end-to-end fill is not (F1).
  • No account-based performance figure exists. No signed-account fills were supplied; paper results are hypothetical and do not model fees, slippage or queue position (F2, A5).
  • High-ROI is not a validated model. It is a rule-based filter; no expected return or external news cause is proven (A1, A4).
  • Alert coverage is partial. The browser watches a limited open-market universe and only records while the page is open (A2, A6).
  • The gas topic was empty in the demo environment's 1,000-event scan on 2026-11-20 (F4).
  • Streaming is unconfirmed in a browser; configurable polling is used (F10).
  • The public rate-limit budget is unpublished (F3).
  • The model shortlist is a screen, not a validated edge. Its hit rate is now measured on settled demo markets, but that sample is small and the demo environment is not production (F13).
  • Causal attribution for a price jump is not available from official sources: Kalshi publishes where a market is decided, not what moved its price (F14).
  • Simulated trades carry no fees, spread or slippage, so the strategy P&L is optimistic by an unknown amount (F15).
  • A test-only dependency has a moderate advisory; see A10. The static site has no runtime npm dependency.

6 · How this site stays honest

Blank beats wrong

A value the API did not return renders as n/a, not zero. A price of $0.00 and a missing price are different facts.

Every row is traceable

Computed figures name their formula inline; API figures name the endpoint. The Verification page links each claim to its official source.

Limits are stated, not hidden

The seconds-resolution gap and the accumulate-from-live approach are written on the chart itself, so the line is never mistaken for exchange history.

7 · Method

Facts were captured from the official API by CI, because the build sandbox cannot open TLS connections to Kalshi hosts. Each capture is committed to reports/ with a timestamp and the commit it ran against, so every claim can be re-derived. Documentation claims link to docs.kalshi.com ↗. Signing rules were additionally proved by a deterministic 6-check self-test.
