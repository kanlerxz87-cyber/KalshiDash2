How this chart is built, and what it cannot show
  • 1 hour and shorter: points come from the 1-minute candlestick endpoint GET /series/{series_ticker}/markets/{ticker}/candlesticks, requested with period_interval=1. The snapshot stores the last 6 hours, so all of these windows are covered by real candles. (docs)
  • 24 hours and 7 days: the snapshot only stores 1-minute candles for 6 hours. Longer windows are drawn from those same candles, so the line starts when the collected candles start. It is not extrapolated backwards.
  • Seconds: the public REST API has no sub-minute history endpoint. A true seconds view needs either the authenticated WebSocket ticker channel or repeated polling, both of which require this page to reach the API directly from your browser. Kalshi does not document CORS support for that, so it is opt-in and reported honestly (see Flagged F1).
  • y axis is the yes-side contract price in dollars (0.00–1.00). The snapshot plots the candlestick price.close_dollars field verbatim.

Why there are no asks in this table

Kalshi returns bids only for each side. A yes bid at price X is the same trade as a no ask at 1 − X, so the two sides contain the full book. The "implied ask" columns apply that documented conversion (orderbook responses). Arrays are sorted ascending and the best bid is the last element.

What this dashboard does not know

  • Historical snapshots accumulate only while the collector runs. The first snapshot has no prior value, so no change-over-time metric is shown until a second snapshot exists.
  • Topic coverage reflects the exchange taxonomy at collection time. Series that are added or retagged after a snapshot are not reflected until the next run.
  • Demo markets use mock funds and may not track real prices (demo environment).
