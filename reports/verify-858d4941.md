## 2. Defect 1 — the guards were orphaned (the class defect)

### Measured

```
$ for f in tests/*.test.mjs; do
    b=$(basename "$f")
    grep -rq "$b" .github/workflows/ || echo "NOT IN CI: $b"

NOT IN CI: page-identifiers.test.mjs
NOT IN CI: probe-citation-drift.test.mjs
```

Exactly the two guards written in response to production incidents:

| Guard | Shipped by | Why it exists |
|---|---|---|
| `tests/page-identifiers.test.mjs` | PR #129 | After PR #126 shipped `ReferenceError: repeated is not defined`, `render()` threw inside `loadBoard()`'s `try`, so **every load of the homepage** showed *"Could not load events: repeated is not defined"*. `.github/workflows/` mentioned either one.**

  dropped), a step naming both guards, and a step running the new coverage test.
- `tests/ci-coverage.test.mjs` *(new, 6 checks)* — fails if any `tests/*.test.mjs` file is
  unreferenced; requires `site-check.yml` to run the glob; requires every test file a
  workflow names to exist; requires the two named guards to be covered; requires the pinned
  probe capture to stay pinned and dated; and pins the Flagged-page disclosure correction (§5).

## 3. Defect 2 — the probe artifact carried no capture time

### Measured

Probe run [`46037867319`](https://github.com/kanlerxz87-cyber/KalshiDash2/actions/runs/46037867319)
(`schedule`, `createdAt` 2026-11-27T16:57:08Z, `updatedAt` 2026-11-27T16:57:29Z) rewrote the
rolling artifact at `bb4ede5`:

| Field | Site published | Committed at `bb4ede5` |
|---|---|---|
| Elections | 5,430 | **5,472** |
| Sports | 8,492 | **8,496** |
| Entertainment | 5,257 | **5,259** |
| `series_rows_in_single_response` | 16,698 | **17,023** |
| Social / Crypto / Culture | 100 / 642 / 4 | 100 / 642 / 4 (unchanged) |

The artifact's own key list at that commit:

```
categories, cors, endpoints, series_rows_in_single_response, tags, websocket
```

**No timestamp field of any kind.** The only record of "when" was the git commit time, which
a browser cannot read. That is the mechanism behind Flagged C1 — and it survived C1's fix,
because C1 corrected the *stamp*, not the *missing field*.

### Changed

- `.github/workflows/probe.yml` — writes `"captured_at": datetime.now(timezone.utc)` into the
  artifact at the **start** of the run (so the stamp bounds the whole capture); adds the
  `datetime` import; prints the stamp in the run log. Validated: the file parses as YAML and
  its embedded Python compiles.
- `data/probe/api_surface.json` — back-filled `captured_at: "2026-11-27T16:57:29Z"` from the
  run that generated it.
- `data/probe/api_surface_2026-11-24.json` — the **pinned** copy PR #131 introduced, which the
  site's figures now cite. Back-filled `captured_at: "2026-11-24T18:14:00Z"`.
- **The back-fill is disclosed inside each file** as `captured_at_basis`, because a stamp
  added afterwards is not the same evidence as one written at capture. For the pinned file
  the record says explicitly that **only the minute is evidenced** — the date comes from
  session `74b579c8`'s own note (*"last rewritten `2026-11-24T18:14Z`"*,
  `reports/verify-74b579c8.md`), which every published citation on the site has carried since;
  the seconds are written `00` and must not be read as measured.
- `tools/test_collect.py` — `ProbeArtifactContractTests` (5 checks) requires both artifacts to
  carry a stamp, requires `probe.yml` to keep writing it, requires the pinned file never to be
  opened for writing, and requires a back-filled stamp to carry its basis.

## 4. Defect 3 — the collector summary read a retired key

### Measured

Four consecutive `Collect demo snapshot` runs failed:

|---|---|

Step-level detail for `45968392940`:

```
4 Collect snapshot             -> success
5 Summarise                    -> failure
6 Validate snapshot metadata … -> skipped

```

Collection succeeded; the job died immediately after. Cause, from the committed snapshot:

```
$ python3 -c "import json; print(sorted(json.load(open('data/snapshot.json'))['topics']['gas']))"
['events', 'label', 'markets', 'rule', 'series', 'series_rows_kept_for_topic', 'source']
```

`series_count` is **absent** — PR #129 retired it as part of Flagged C1 precisely because the
name read like a catalogue size. `scripts/collect.py:692` writes
`series_rows_kept_for_topic`. But `.github/workflows/collect.yml` still formatted:

```python
print(f"  {k:10s} series={t['series_count']:4d} …")
```

Reproduced locally against the committed snapshot:

```
REPRODUCED KeyError: 'series_count'
```

The snapshot had therefore not refreshed since `2026-11-25T08:51:27Z`, and no test read the
workflow, so nothing noticed. **The rename was verified by a test; the workflow that consumed
the renamed key was not.**

### Changed

- `.github/workflows/collect.yml` — reads `series_rows_kept_for_topic`, and raises an explicit

- `tools/test_collect.py` — `WorkflowSummaryContractTests` (3 checks): the workflow must not
  read the retired key; every key the summary reads must exist in the committed snapshot; the

## 5. Defect 4 — the Flagged page claimed a source link it does not have

Found by auditing every card while confirming §2's edit had not disturbed the counters.

**The page's "How to read this page" panel said:** *"Every item has an ID, the evidence that
produced it, and an official source link."*

**Measured across all 100 cards:**

```
total cards: 100
cards WITH an official source link: 94
cards WITHOUT one:                    6   -> A2, R2, Y9, Y10, Y11, NF1
```

`NF1` cites official pages inline (as `<a>` elements inside a `<ul>`) rather than through the
`src-link` class, so it is correctly sourced and was **not** a defect. The other five are
process findings **about this repository**, not claims about Kalshi:

| Card | Finding | Why no official source can exist |
|---|---|---|
| A2 | Alerts are only recorded while a browser tab is open | Describes this site's hosting |
| R2 | Parallel-claim races between agent sessions | Describes this repo's coordination |
| Y9 | `assets/js/jumps.js` was dead code | A deleted file in this repo |
| Y10 | A duplicate `docs/` site generation is still published | This repo's build output |
| Y11 | The "High-ROI" chat is a rule-based screen, not a model | A property of this site |

**No link was invented to close the gap.** Inventing an official URL for a finding about a
deleted local file would be exactly the fabrication this repository's verification rule
forbids. Instead:

- The panel's absolute sentence was **corrected** to *"Items about Kalshi's API or data carry an
  official source link"*.
- A disclosure was added **naming all five items** and stating that the page previously
  claimed otherwise — recorded as a wrong claim, with the findings themselves left intact.
- `tests/ci-coverage.test.mjs` now fails if the absolute wording returns, if the disclosure is
  removed, or if any of the five named cards disappears.

## 7. Conflict record — PR #131 (session `bacbd8a9`) merged mid-session

**What happened.** While this session's PR #132 was open, PR #131 (*"Withhold malformed trade
totals and pin dated probe evidence"*) was merged into `main` at `da6c723`. It **fixed the same
citation drift, differently and better**:

| | This session's original fix | PR #131's fix |
|---|---|---|
| Approach | refresh the published figures to the current capture, carry its stamp | **pin** the figures to an immutable dated copy, `data/probe/api_surface_2026-11-24.json` |
| Effect | the figures are right **today** | the figures **cannot drift again** |

**Resolution — PR #131's approach adopted, this session's figure refresh withdrawn.** Editing
`flagged.html` / `assets/js/claims.js` to newer figures would have contradicted #131's pinned
citations and undone a strictly better design. Following the board's standing rule (*keep the
canonical `main` version, do not discard the other session's work*), the branch was reset onto
`main` @ `956e704` and only the **non-overlapping** work was re-applied:

| Re-applied (no overlap with #131) | Withdrawn (superseded by #131) |
|---|---|
| CI wiring of the two orphaned guards + `tests/ci-coverage.test.mjs` | the figure updates in `flagged.html` / `claims.js` |
| `collect.yml` `series_count` → `series_rows_kept_for_topic` fix | the original rolling-artifact `captured_at` back-fill rationale |
| `captured_at` written by `probe.yml` on every run | |
| `captured_at` stamped on the **pinned** file, from reviewed evidence | |
| `WorkflowSummaryContractTests` + `ProbeArtifactContractTests` | |
| the Flagged-page disclosure correction (§5) | |

**Nothing from #131 was modified, reverted, or discarded.** `data/probe/api_surface_2026-11-24.json`
gains only the two additive metadata keys; its `categories`, `tags`, `cors`, `websocket` and
`series_rows_in_single_response` values are byte-identical to #131's.
